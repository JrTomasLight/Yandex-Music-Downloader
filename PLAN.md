# План разработки

Цель первой версии (0.1.0): вошедший пользователь нажимает «Скачать» на странице альбома, плейлиста или исполнителя
Яндекс Музыки — и треки, доступные ему по подписке, оказываются в выбранной папке, с понятными именами, тегами
и обложкой; повторное нажатие докачивает только новое.

Порядок этапов выбран так, чтобы как можно раньше проверить главный риск (этап 1), а дальше каждый этап
заканчивался работающей проверяемой частью. Сделанное отмечать `[x]`.

## Этап 1. Разведка сайта — вместе с вами, под вашим входом
Главный риск проекта: в каком виде сайт отдаёт сами файлы. Пока это не выяснено, дальше ядра не идём.
- [ ] Адреса страниц в текущем интерфейсе: альбом, трек, исполнитель, плейлист пользователя, плейлист по uuid,
      «Мне нравится», домены (`.ru/.by/.kz/.uz/.com`). Сверить с `parseLink`, поправить тест.
- [ ] Какие запросы делает сама страница (вкладка «Сеть» в DevTools): адрес API, как передаётся вход
      (cookie сайта или токен со страницы), ответ для альбома, плейлиста (постранично?), исполнителя.
- [ ] Как страница получает ссылку на файл трека: какие форматы и качество доступны по подписке, сколько живёт ссылка.
- [ ] **Решающая точка.** Если файл отдаётся открыто (например, обычный mp3) — качаем его. Если только в защищённом
      виде — такие треки не скачиваем (правило в `CLAUDE.md`), останавливаемся и решаем, что делать дальше.
- [ ] Ограничения: как сайт отвечает на частые запросы (429, капча), сколько запросов в секунду безопасно.
- [ ] Обезличенные образцы ответов — в `test/fixtures/` (без логина, токенов, cookie). Итог — раздел «API сайта»
      в `CLAUDE.md`.

## Этап 5. Сбор с сайта
- [ ] `content.js`: запросы к API сайта из его вкладки с тайм-аутом, повторами, долгой паузой на 429 и сообщением
      «повторю через …»; защита от повторного внедрения после перезагрузки расширения.
- [ ] Сбор альбома (с дисками), плейлиста (постранично), трека, исполнителя (что входит в дискографию — решить:
      альбомы, синглы, сборники).
- [ ] Единый формат задачи для вкладки загрузок: название, папка, список треков (номер, диск, id, название,
      исполнители, альбом, год, обложка, длительность, доступен ли). Ссылка на файл берётся прямо перед
      скачиванием трека, а не при сборе.
- [ ] Недоступные треки (нет в подписке, удалены, только защищённый поток) — пропускаются, в итоге видно, сколько
      и почему.
- [ ] `test/content.test.cjs` на образцах из `test/fixtures/`: альбом, длинный плейлист, зависший запрос, 429 с повтором,
      недоступные треки.
