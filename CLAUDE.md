# Yandex Music Downloader

Расширение для Chromium-браузеров (Chrome, Edge, Яндекс Браузер, Opera), Manifest V3. Устанавливается
локально — «Загрузить распакованное расширение» из папки, без магазина; обновляется в один клик с GitHub.
Скачивает с Яндекс Музыки альбомы, плейлисты, треки и дискографии, доступные вошедшему пользователю
по его подписке, в выбранную им папку на диске.
Репозиторий: https://github.com/JrTomasLight/Yandex-Music-Downloader

План работ и порядок этапов — в `PLAN.md`; отмечать там сделанное.

## Правила
- **Никаких `Co-Authored-By` и других упоминаний Claude в коммитах и PR.** Обычные сообщения коммитов, на русском.
- Общение, тексты интерфейса, README и CHANGELOG — на русском.
- Коммитить, пушить, ставить теги и выпускать релизы — только когда пользователь попросил.
- README.md пользователь правит сам (в том числе через веб на GitHub): перед правкой делать `git pull`
  и менять текст точечно относительно текущей версии, не переписывая его стиль.
- Внутренний API сайта не документирован. Расширение работает только от имени вошедшего пользователя
  в его браузере и берёт то, что сайт и так отдаёт этому пользователю по его подписке.
  Не подделывать запросы в обход входа и ограничений сайта, не снимать шифрование и защиту контента:
  трек, который сайт отдаёт только в защищённом виде, не скачивается — пропускается с понятным объяснением.

## Устройство (`extension/`)
- `manifest.json` — версия расширения (единственное место, где она задаётся; страницы читают её оттуда).
  Поле `name` не менять: по нему обновление узнаёт папку и архив своего расширения.
- `common.js` — общее для всех частей: этапы задач (`ACTIVE`, `isActive`), разбор ссылок Яндекс Музыки
  (`parseLink` → альбом / трек / исполнитель / плейлист), ключ задачи (`keyOf`), `safeName`.
  Подключается в background (`importScripts`), на страницах, в manifest перед скриптом кнопки и вместе с `content.js`;
  поэтому без объявлений верхнего уровня (`self.EXT = …`).
- `update.js` — обновление в один клик с GitHub (готово, настроено на репозиторий и архив `yandex-music-downloader-<версия>.zip`).
- Ещё не написаны (см. `PLAN.md`): `background.js`, `content.js`, `button.js` (кнопка на сайте),
  `downloader.html/js` (вкладка загрузок), `popup.html/js`. Пока их нет, manifest ссылается на отсутствующие файлы
  и расширение в браузер не загрузится.

## Образец для переноса (`reference/`)
Локальная папка, в git не входит (`.gitignore`). В `reference/sample/` — исходник рабочего
расширения-загрузчика с другого сайта, из которого переносится ядро, не зависящее от сайта: папка, скачивание,
очередь, повторное скачивание, фоновый скрипт, вкладка загрузок. Карта «что где лежит» — `reference/PORTING.md`.
Переносить по смыслу, а не копировать файл целиком: всё, что про тот сайт, заменяется своим, упоминаний
о нём в коде и текстах проекта быть не должно. Когда ядро перенесено, папку `reference/` удалить.

## Грабли, на которые уже наступили
- `display:flex` (и любой `display`) у блока перебивает атрибут `hidden` — в стилях страниц всегда
  `[hidden] { display:none !important; }`. Проверять видимость на экране, а не атрибут.
- Состояние в `chrome.storage.local` переживает перезапуск расширения и браузера. Этапы «идёт» после
  перезапуска надо сбрасывать (`resetJobs` в `onInstalled`/`onStartup`), а застывшие — не считать идущими (`isActive`).
- Очередь в storage меняют сообщения из разных мест — менять только через одну цепочку (`editPending`),
  иначе одновременные изменения затирают друг друга.
- Нельзя запускать второй сбор того же объекта (обновили вкладку загрузок посреди сбора, нажали кнопку ещё раз):
  два сбора пишут свой счётчик наперебой, а объект встаёт в очередь дважды.
- Сбор заранее — только для ближайших 1–2 задач, иначе при длинной очереди собирается всё сразу,
  сайт отвечает 429, а собранное успевает устареть. Ссылки на файлы у музыкальных сервисов обычно
  живут недолго — брать ссылку на файл прямо перед его скачиванием, а не на этапе сбора.
- Если открыто несколько вкладок загрузок, качать должна одна (`navigator.locks`, замок `ymd-queue`). Замок может
  держать «невидимая» страница — ждать только пока у владельца свежая отметка, иначе забирать (`steal`); забравшая
  вкладка прерывает текущую загрузку у прежней, не убирая задачу из очереди.
- Не открывать новую вкладку загрузок, если она уже есть: `chrome.runtime.getContexts` (session storage
  с id вкладки теряется при перезапуске расширения).
- После перезагрузки расширения старый внедрённый скрипт на странице сайта «мёртв», но его глобальный флаг
  остаётся — флаг должен быть функцией, проверяющей `chrome.runtime.id`.
- Windows: запрещены `<>:"/\|?*`, точка и пробел в конце имени (в том числе после обрезки по длине),
  имена устройств `CON`, `NUL`, `COM1`… даже с расширением. Всё это делает `safeName`.
- В заголовках запросов допустима только латиница — кириллицу в адресе кодировать.
- Текстовые файлы для Блокнота: UTF-8 с BOM и переводы строк `\r\n`.
- Если сайт отдал подозрительно мало элементов (меньше 80% от ожидаемого), ничего не переносить в «убранные».
- Сервер может зависнуть посреди ответа: тайм-аут на начало ответа, на паузу между кусками данных и на тишину
  сбора (сторож в `waitFilled`), повторы с паузами.
- Уведомления — одно на серию и только когда вкладка загрузок в фоне; новое заменяет прежнее (постоянный id).
- В Яндекс Браузере расширение загружено из папки — обновление в один клик пишет файлы прямо в неё
  (антивирус может мешать: подсказать в ошибке и README).

## Проверка
Сборщика нет. Перед коммитом:
- `node --check extension/*.js`
- `node --test "test/*.test.cjs"` — тесты в Node без браузера.

Тесты (`test/`): `stub.cjs` — заглушки `chrome.*` (storage с `onChanged`, события, `message` как от браузера),
`loadScripts` (файлы расширения в один `vm`-контекст, как `importScripts`), `memoryDir` (папка в памяти
с интерфейсом File System Access). На каждую перенесённую часть — свой `<часть>.test.cjs`; сценарии, которые
обязательно покрыть, перечислены в `PLAN.md`. Ответы сайта в тестах — поддельный `fetch` по образцу
настоящих ответов (сохранять их в `test/fixtures/`, без личных данных и токенов).

Логику страниц проверять на стенде: `test/stand/srv.py` (локальный сервер, умеет медленные, зависающие
ответы и коды ошибок), страница-стенд с заглушкой `chrome` (`new Function('chrome', code)`), папка — OPFS
(`navigator.storage.getDirectory()`); `test/stand/zombie.html` — вкладка, которая держит замок очереди.
Поведение под входом на Яндекс Музыке подтверждает пользователь. Временные `.claude/launch.json` после проверки удалять.

## Релиз
Автоматический (`.github/workflows/release.yml`), подробно — в `RELEASING.md`:
1. Поднять `version` в `extension/manifest.json`.
2. Добавить раздел `## <версия>` в начало `CHANGELOG.md` по шаблону из его шапки (Новое / Изменено / Исправлено),
   без инструкции по установке — её добавляет workflow из `.github/release-template.md`.
3. Коммит, `git push`, затем `git tag <версия>` и `git push origin <версия>`.
Workflow сверяет тег с версией, собирает `yandex-music-downloader-<версия>.zip` и публикует релиз с текстом из CHANGELOG.
Архивы `*.zip` в репозиторий не коммитятся. Теги без `v`.
В архиве релиза `manifest.json` должен лежать в корне — на этом держится обновление в один клик.
